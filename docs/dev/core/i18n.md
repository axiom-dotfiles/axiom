# Translation (i18n)

> **Files:** `config/I18n.qml`, `config/i18n/<code>.json`, `scripts/check_i18n.py`
> **Config:** `General.language`
> **Related:** [Schema annotations](schema-annotations.md), [Settings page](settings-page.md)

How user-visible text is translated. The rules themselves are in AGENTS.md › Translation; this doc adds the mechanics.

### Source language
- `General.language` picks the language.
- English is the source: user-visible text is written in English, inline, as `I18n.tr("Text")`.
- **Dynamic values** use placeholders, so the whole sentence stays one key: `I18n.tr("{0} updates", count)`. Never template-string sentences.

### Dates and times
- Through `I18n.formatDate(date, format)`, never `Qt.formatDateTime`, so day and month names follow the language.
- Named formats: `I18n.dateFormat("longDate" | "mediumDate" | "shortDate" | "monthYear" | "fullDate" | "dateTime" | "time24" | "time12")`.

### Schema forms translate themselves
- The generic `Schema*` form widgets translate their own `label` / `title` / `description` and dropdown option labels.
- Callers pass English; schema titles and descriptions need no code.

### Languages
- Adding a language = adding `config/i18n/<code>.json`:
  `{"_meta": {"name", "locale", "formats"}, "strings": {english: translation}}`.
- It then appears in the language dropdown (`x-options: "languages"`).
- Missing entries fall back to English.
- The active dictionary reloads live when edited. Write it atomically (temp file + rename), since a half-written file gets read.

### Checking coverage
- Run `scripts/check_i18n.py` after changing text: it lists missing and unused entries.
  - `--fill` adds the missing ones, empty.
  - `--untranslated` finds UI literals not wrapped in `tr()`.
- Keys chosen only at runtime (e.g. `I18n.tr(form.shape)`) must be declared in a comment next to the call, as `I18n.tr("square") ...`, so the checker sees them.
- Leave developer-facing strings in English: logs, validation errors, migration notes.
